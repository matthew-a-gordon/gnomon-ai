# Store functions run as the invoker, and only Erasure, Kind registration, the merge-rule setter and the search index trigger are definers

The Store's read and write functions are `SECURITY INVOKER` with `search_path = ''`, so every call runs as the caller under RLS. Caller roles may update only the Recorded-time end column of a Version, and may delete a Version or a Citation only when the current transaction wrote it. Guard triggers enforce both. The update guard lets the Recorded-time end change only by closing an open Version when the current transaction started, apart from replacing a Version written earlier in the same transaction, which may also reopen a Version that transaction closed. The delete guard refuses any row an earlier transaction wrote. Each row is marked at insert with the transaction that wrote it, and no caller may supply or change the mark. Erasure is the only route that deletes committed history. Erasure, Kind registration and the merge-rule setter, `gnomon.set_merge_rule`, are `SECURITY DEFINER` functions owned by a NOLOGIN gnomon role. Erasure is one definer function for each thing it erases: `gnomon.erase_episode`, `gnomon.erase_node`, `gnomon.erase_edge` and `gnomon.erase_scope`. The definer role reads under the caller's Tenant and Scope policies. Its one wider policy lets an Erasure read and delete, in the caller's Tenant, the Edges of any Scope that join a Node it erases, and the Summaries of any Scope that describe that Node with their Citations, because the Node cannot go while they stand. Each checks the Tenant against `gnomon.tenant_id()`, and each deployment decides who may execute any of them. The setter is a definer for the reason Kind registration is: a Kind's rule changes after registration, and no caller may write `kind_merge` directly. The search index trigger, `gnomon.maintain_search_index`, is the fourth definer. It is the trigger function that writes Search's token rows and BM25 counts, Resolution's rows of each Node Version's names and Aliases, and the token rows of Summaries and Communities, from the Versions, Sentences, Summaries and Communities a write inserts or deletes (ADR-0010). When a Sentence is stored or replaced, it also deletes the Version's embedding of a text the Version no longer has, and that text's full vector unless another embedding or name row of the Scope still uses it, because callers may not delete embeddings and a stale one would outlive an Erasure. It is owned by the same NOLOGIN role and granted to no role, so no caller can execute it or attach it to a table of its own, and callers hold no write privilege on the search tables but the bits of a name row, which a trigger sets from the stored embedding of the name whatever the caller writes. It runs under the caller's claims and the definer's policies, and writes only for the Tenant and Scope of the rows that fired it. It is a definer because an invoker trigger needs callers to hold write privileges on the search tables, and a caller could then write them from a trigger of its own on a temporary table. We chose this because RLS stays the barrier between Tenants on every ordinary call, and only the operations that must delete history, write the Ontology or write Search's derived rows run with more privilege.

## Considered options

- Every function `SECURITY DEFINER`, with callers holding EXECUTE only. No direct DML is possible, but RLS policies for caller roles stop applying, and each function's own Tenant check becomes the only barrier. One bug is a cross-tenant write.
- No DELETE at all, with a replaced Version closed at its own Recorded-time start. That leaves an empty Recorded time, which ADR-0008 refuses, and a dead row with its Citations.
- Invoker triggers for the search tables, with a guard that refuses a write below a trigger depth of 2. Every role may create a temporary table and a trigger on it, so a caller reaches that depth from a trigger of its own and writes the token rows and counts of its own Scopes.
- A further definer function that deletes only rows the current transaction wrote. It would run with more privilege than the write it serves, for a case the guard covers.
